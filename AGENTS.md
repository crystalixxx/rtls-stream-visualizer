# Руководство для Codex при ревью кода

Этот файл описывает, на что агенту стоит обращать внимание при ревью изменений в этом репозитории.

## Общие принципы ревью
- Сначала ищи баги, регрессии, риски гонок/утечек ресурсов и нарушений контрактов API.
- Проверяй корректность обработки ошибок, поведение в граничных условиях, что логов достаточно для деббага приложения.
- Обращай внимание на совместимость с Python >= 3.12.

## Тесты
- Для любой логики, которая меняет поведение, добавляй или обновляй тесты.
- Отсутствие тестов в изменениях, которые влияют на бизнес‑логику, считаем блокером.
- Если тесты неочевидно писать, требуй объяснение в PR (почему тест не добавлен).
- При добавлении тестов используй существующие фикстуры и `tests/**/static` для файлов.

## Форматирование и стиль
- Код должен проходить форматирование `black`.
- Не принимай изменения с нарушением `black`‑формата.
- Новые файлы и правки должны быть совместимы с текущими настройками `pyproject.toml`.

## Python best‑practice
- Явно закрывай ресурсы (сокеты, файлы), избегай висящих потоков.
- Не добавляй зависимости на стандартную библиотеку в `pyproject.toml`.
- Избегай избыточной сложности: предпочитай простые и читаемые решения.
- Не меняй публичные интерфейсы без явной причины и миграционного пути.

## Конкретика по проекту
- UDP‑код: проверяй корректность работы с сокетами, таймаутами и закрытием.
- Валидация данных: тестируй ошибки JSON/схем и корректный разбор файлов.
- Логи: не спамь логами в tight‑loops, но фиксируй ошибки.
